Here is the complete, start-to-finish guide to migrating your application configuration to a Helm-managed ConfigMap. This covers moving your actual .yml files, merging them correctly, and injecting them into your Spring Boot container.
### Phase 1: Relocate Your Configuration Files
To manage your configuration through Helm, the files must live inside the Helm chart directory, not inside your application's source code.
 1. Create a new directory named config inside your Helm chart folder: **helm/helm-train1/config/**
 2. Move all your environment configuration files out of src/main/resources/ and into this new config directory.
 3. Your Helm directory should now look like this:
   ```text
   helm/helm-train1/
   ├── config/
   │   ├── application.yml
   │   ├── application-dev.yml
   │   ├── application-cob.yml
   │   └── ... (other env files)
   
   ```
*(Note: Removing them from src/main/resources/ ensures they aren't permanently baked into your .jar file, making Helm your single source of truth).*
### Phase 2: Define Configuration Paths in Values
Helm needs to know which files to combine depending on the environment being deployed.
 1. **Open helm/helm-train1/values.yaml** (Your base values file).
   Add the default paths at the top or bottom of the file:
   ```yaml
   # Base configuration applied to all environments
   baseConfigPath: "config/application.yml"
   
   # Default environment configuration (acts as a fallback)
   envConfigPath: "config/application.yml" 
   
   ```
 2. **Open helm/helm-train1/dev1-dubhe-values.yaml** (Your Dev environment values file).
   Override the envConfigPath to point to the dev-specific properties:
   ```yaml
   # Overrides the fallback to use Dev properties
   envConfigPath: "config/application-dev.yml"
   
   ```
*(Repeat step 2 for your other environment value files, pointing to -cob.yml, -sit.yml, etc.)*
### Phase 3: Build the ConfigMap Template
Since you are using .yml files instead of flat .properties files, we must join them using the standard YAML multi-document separator (---). Spring Boot will read this as a single file and apply the environment overrides perfectly.
 1. Create a new file: **helm/helm-train1/templates/configmap.yaml**
 2. Paste in the following code:
   ```yaml
   {{- $BaseConfigPath := .Values.baseConfigPath -}}
   {{- $EnvConfigPath := .Values.envConfigPath -}}
   
   apiVersion: v1
   kind: ConfigMap
   metadata:
     name: {{ .Values.APP_NAME }}-cm
     namespace: {{ .Release.Namespace }}
   data:
     application.yml: |-
   {{ .Files.Get $BaseConfigPath | nindent 4 }}
       ---
   {{ .Files.Get $EnvConfigPath | nindent 4 }}
   
   ```
### Phase 4: Inject the ConfigMap into Your Deployment
Now we mount that ConfigMap directly into the container's file system so Spring Boot can read it on startup.
 1. **Open helm/helm-train1/templates/deployment.yaml**.
 2. Find your containers: block. Add the SPRING_CONFIG_ADDITIONAL_LOCATION environment variable and the volumeMounts:
   ```yaml
         containers:
           - name: lds-integrating-service
             image: ...
             env:
               # Forces Spring Boot to look in /etc/config/ for properties
               - name: SPRING_CONFIG_ADDITIONAL_LOCATION
                 value: "file:/etc/config/"
               # ... (keep your other existing env vars here) ...
   
             volumeMounts:
               - name: {{ .Values.APP_NAME }}-app-volume
                 mountPath: /etc/config
   
   ```
 3. Scroll down to the bottom of the template.spec (at the same indentation level as containers:) and define the volume:
   ```yaml
         volumes:
           - name: {{ .Values.APP_NAME }}-app-volume
             configMap:
               name: {{ .Values.APP_NAME }}-cm
   
   ```
### Phase 5: Deploy and Verify
You are now ready to deploy. When Helm packages this release, it will dynamically fetch application.yml and application-dev.yml, stitch them together, and hand them to the pod.
**To verify it worked:**
Once your pod is running, execute into it to check the mounted file:
```bash
kubectl exec -it <your-pod-name> -n <your-namespace> -- cat /etc/config/application.yml

```
You should see the contents of your base application.yml, followed by ---, followed by your environment-specific application-dev.yml. Spring Boot will automatically prioritize the properties below the --- separator.
